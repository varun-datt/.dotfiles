# Document mode

One document: a design, a plan, a long note, a report, a handoff. It may be the record itself, or a draft whose parts belong elsewhere.

## Step 2 additions

1. Read it whole, then split it into claims: decisions with their reasons, facts, rules, procedures, open work.
2. For each claim, check whether a home already holds it (step 1's homes, and the repository's `docs/`, decisions and `AGENTS.md`). A claim already held is dropped from the move and noted as a duplicate.
3. Check each claim against the code or the cited source, as research mode's "Verify before importing" says; a document drifts from the code once written.
4. Mark what is stale: a step already done, a gap since closed, a plan overtaken by a decision.

## Step 6 additions

- If the document stays the home for most of its claims, leave it in place, cut the claims you moved into a link to their new home, and fix what was stale.
- If its parts all moved, archive it where the repository keeps finished work, or delete it if it is tracked; ask before removing an untracked file.
- Never rewrite a dated decision or event note: write a new one that supersedes it and links back.
